### base-foundation

**Purpose:** The root of everything. Core abstractions and utilities consumed by all other modules.
**Entry point:** `build.base.foundation`
**Key files:**

| File | Purpose |
|---|---|
| `Lazy<T>` | Thread-safe, once-initialized optional-like container. Supports `map()`, `filter()`, `computeIfAbsent()`. |
| `Capture<T>` | Mutable, clearable `Optional`-like container. Ideal for lambda side-channel returns. |
| `Exceptional<T>` | Either-monad for value-or-exception. Wraps checked exceptions from suppliers. |
| `Streamable<T>` | `@FunctionalInterface` bridging `Iterable<T>` to `Stream<T>` with lazy `map()`/`filter()`. |
| `Streams` | Stream utilities: `zip`, `topologicalSort`, `sortByRequires`, `reverse`. |
| `Strings` | Rich string utilities + registry-based `convert(String, Class<T>)` for all common types. |
| `Introspection` | Memoized reflection: full type hierarchy traversal for fields, methods, annotations. |
| `Preconditions` | Returns-its-argument validation: `requireNonNull`, `require(Predicate)`, etc. |
| `ConcurrentWeakHashMap` | `ConcurrentMap` with weak keys and pluggable `Hasher<K>` strategy. |
| `Memoizer<K,V>` | Per-key-locking function memoization backed by `ConcurrentWeakHashMap`. |
| `AtomicEnum<T>` | Synchronized mutable enum wrapper with CAS semantics. |
| `TransformingIterable<T>` | Lazy fluent `Iterable` with `map`, `filter`, `distinct`, `flatten`, `abort`. |
| `iterator/matching/` | Regex-like DSL for pattern matching over `Iterator<T>`. Composable conditions with capture. |
| `predicate/Predicates` | `always()`, `never()`, `anyOf()`, `allOf()`, descriptive wrappers. |
| `tuple/Pair`, `Triple` | Immutable typed tuples; output of `Streams.zip()`. |
| `unit/MemorySize` | IEC + SI memory unit enum with parsing and pretty-printing. |
| `Primes` | Pre-computed prime table (2–9973) with O(log n) lookup. |

**Exports:** All sub-packages (`iterator`, `iterator.matching`, `predicate`, `stream`, `tuple`, `unit`).
**Dependencies:** `java.sql` (for `Strings.convert` on `Date` types).

### base-expression

**Purpose:** Native Jakarta EL 6.0 implementation — parsing, AST, evaluation, and type coercion. Registered as a Jakarta EL `ExpressionFactory` SPI so `ExpressionFactory.newInstance()` discovers it automatically. The high-level `Processor`/`Variable` API is still present but marked `@Deprecated` — callers should migrate to the Jakarta EL API directly.

| Type | Role |
|---|---|
| `el.ExpressionFactoryImpl` | `ExpressionFactory` SPI entry-point; discovered via `module-info provides` |
| `el.ValueExpressionImpl` | Full `ValueExpression` — evaluates, assigns, reports read-only status |
| `el.MethodExpressionImpl` | `MethodExpression` — handles both `${bean.method}` reference and `${bean.method(arg)}` call forms |
| `parser.ELParser` | Extends `AbstractParser<Node>`; recursive-descent operator-precedence grammar; three static entry points: `parseFull`, `parseComposite`, `parseExpression` |
| `ast.Node` (sealed) | AST hierarchy root — 12 permitted record/class subtypes covering all EL expression forms |
| `eval.NodeEvaluator` | Visitor-style evaluator via pattern-matching `switch` over the sealed `Node` hierarchy |
| `eval.TypeCoercion` | EL spec §1.23 coercion: all primitives, `BigDecimal`, `BigInteger`, `Character`, enums |
| `eval.Arithmetic` | EL spec §§1.7–1.9: promotion chain `BigDecimal` > `Double` > `BigInteger` > `Long` |
| `compat.Processor` | **Deprecated** high-level facade; wraps `ELProcessor` — retained for migration |
| `option.ResolvableOption<T>` | Active (not deprecated): `Option` that resolves itself via a `Processor` |

**Gotchas:**
- `build.base.expression.el` is **not exported** — its `public` types are module-internal only.
- EL string escape sequences: only `\"`, `\'`, and `\\` are expanded; `\n`, `\t`, `\r` are passed through as literal two-character sequences.
- `MethodExpressionImpl.invoke`: when the expression embeds args (`${bean.method(x)}`), caller-supplied `params` are silently ignored.

**Dependencies:** `base-foundation`, `base-configuration`, `base-parsing`, `jakarta.el` (API only — this module IS the runtime).

### base-commandline

**Purpose:** POSIX/GNU CLI argument parsing, populating a `ConfigurationBuilder` from `String[]`. Includes a fluent `Command` builder, environment variable fallback, help section grouping, declarative commands/categories, multi-prefix options, and a positional argument consumer.

| Type | Role |
|---|---|
| `CommandLineParser` | Core parser; registers `Option` classes by prefix, parses `String[]` into `ConfigurationBuilder` |
| `CommandLine` | Marker interface + annotation nest; `@Prefix` (repeatable via `@Prefixes`), `@Description`; inner `Argument` class |
| `Command` | Fluent builder: `Command.create("name").argument(...).section(...).option(...).envVar(...).command(...).category(...).build()` |
| `CommandLineParser.UnknownOptionConsumer` | `@FunctionalInterface`; `boolean consume(String arg, ConfigurationBuilder)` |
| `CommandLineParser.HelpException` | `RuntimeException` whose `getMessage()` is the formatted help text |

**Key builder methods:**

| Method | Description |
|---|---|
| `.argument(String label)` | Positional label in `Usage:` line (e.g. `"<task>..."`) |
| `.section(String name)` | Groups subsequent options under a named heading in help |
| `.option(Class<? extends Option>)` | Annotation-driven registration via `@CommandLine.Prefix` |
| `.option(List<String> prefixes, Class, method, description, paramTypes...)` | Multi-prefix registration with explicit help description |
| `.envVar(envVarName, prefix)` | Env var → prefix mapping; matched env vars are prepended before real args |
| `.envVarResolver(Function<String, Optional<String>>)` | Custom env var lookup (useful in tests; `null` disables) |
| `.positionalArgument(Consumer<String>)` | Receives non-hyphen, non-prefix tokens (e.g., task names); preferred over `CAPTURE_UNKNOWN_OPTIONS_AS_ARGUMENTS` |
| `.command(name, description)` | Declares a subcommand for display in `Commands:` help block (no parsing effect) |
| `.category(name, description)` | Declares a category for display in `Categories:` help block (no parsing effect) |
| `.commandsSectionName(String)` | Override `"Commands:"` heading (e.g. `"Tasks:"`) |
| `.categoriesSectionName(String)` | Override `"Categories:"` heading (e.g. `"Aliases:"`) |
| `.helpHandler(Consumer<String>)` | Replaces `HelpException`; `parse()` returns an empty builder when help is invoked |
| `.unknownOption(UnknownOptionConsumer)` | Fallback for unrecognized tokens |
| `.build()` | Constructs and configures a `CommandLineParser`; reflective errors surface here as `IllegalArgumentException` |

**Constants:**

| Constant | Description |
|---|---|
| `IGNORE_UNKNOWN_OPTIONS` | Pre-built consumer; silently accepts all unrecognized tokens |
| `CAPTURE_UNKNOWN_OPTIONS_AS_ARGUMENTS` | Pre-built consumer; wraps non-hyphen unknowns as `CommandLine.Argument` in the builder |

**Multi-prefix options:** A factory method may carry multiple `@CommandLine.Prefix` annotations (repeatable via `@CommandLine.Prefixes`). All prefixes map to the same method; help output collects them on a single row, sorted short-before-long.

**Prefix matching:** Longest-prefix-first (via a comparator-sorted `TreeMap`). Prefix matching uses `startsWith`, not exact match — enabling `-Dkey=value` style (prefix `-D`, remaining passed as first parameter).

**Gotchas:**
- Env-var args are prepended — explicit CLI args always override them (last-write-wins during parsing).
- `=` is globally split before parsing — `--option=foo=bar` becomes three tokens.
- `CAPTURE_UNKNOWN_OPTIONS_AS_ARGUMENTS` does not capture hyphen-prefixed unrecognized tokens; those route to the `UnknownOptionConsumer`.
- `.positionalArgument()` handles non-hyphen tokens before the `UnknownOptionConsumer` sees them. When both are set, the unknown option consumer only sees hyphen-prefixed unknowns.
- `.command()` and `.category()` are purely declarative (help text only) — routing to subcommand logic is the application's responsibility.
- Conflicting prefixes (two `@Prefix`-annotated methods on different classes with the same prefix) throw `IllegalArgumentException` at parse time unless `--option-class <FQN>` precedes the ambiguous token.
- `NoSuchMethodException` from explicit option registration surfaces as `IllegalArgumentException` at `.build()` time, not at `.option(...)` call time.

**Dependencies:** `base-configuration` (transitive), `base-table` (transitive), `base-foundation`.

### base-marshalling

**Purpose:** Annotation-driven, reflection-based object marshalling framework. Converts Java objects to/from a neutral `Marshalled` intermediate form. Wire-format independent. Shallow (non-recursive) by design.

| Type | Role |
|---|---|
| `@Marshal` | Marks the single destructor method; `Out<T>` params receive marshalled values |
| `@Unmarshal` | Marks constructor(s) as unmarshalling entry points; **constructors only** |
| `@Bound` | Marks a constructor parameter as a bound dependency (injected, not from marshalled values) |
| `Marshaller` | Runtime API: `marshal(T)`, `unmarshal(Marshalled<T>)`, `bind(Class<T>).to(value)` |
| `Marshalling` | Global entry point; holds singleton `ConcurrentSchemaFactory`; `register`, `registerEnum`, `newMarshaller` |
| `SchemaFactory` | Maintains registrations; produces `Marshaller` instances |
| `Schema<T>` | Runtime descriptor: `owner()`, `parameters()`, `dependencies()`, `getParameter(String)` |
| `Marshalled<T>` | Intermediate form: `Schema<T>` + ordered `Streamable<Object>` of parameter values |
| `Out<T>` | Write-once output parameter holder for `@Marshal` methods; `Supplier<T>`; non-thread-safe |
| `Dependency` | Named, typed injection point for the marshaller |
| `Binding<T>` / `BindingBuilder<T>` | Fluent API for supplying `@Bound` dependencies: `marshaller.bind(Dep.class).to(value)` |

**Registration patterns:**

```java
// Option A — self-registration (preferred): must call from inside the class
static { Marshalling.register(MyClass.class, MethodHandles.lookup()); }

// Option B — external registration (only if the class is accessible)
Marshalling.register(MyClass.class);

// Option C — enum registration (no lookup required)
static { Marshalling.registerEnum(Color.class); }
```

**Enum marshalling (`registerEnum`):** Enums cannot carry `@Marshal`/`@Unmarshal` (compiler-generated constructors). `registerEnum` creates a synthetic one-parameter schema named `"name"` of type `String`. Marshalling captures `Enum#name()`; unmarshalling calls `Enum.valueOf(enumClass, name)`. Enum schemas are stored separately from regular marshalling schemas and bypass the lookup/reflection machinery entirely.

**Shallow marshalling:** Marshalling is one layer deep. Fields holding other marshallable objects are stored as-is in `Marshalled#values()` — they are NOT automatically marshalled. To serialize nested objects, the `@Marshal` method must accept `Out<Marshalled<NestedType>>` and marshal explicitly.

**Patterns:** Annotation-driven factory dispatch; output-parameter destructor; hierarchical DI via `@Bound`.
**Dependencies:** `base-foundation`.

### base-transport-json

**Purpose:** JSON-format `Transport` implementation for `base-marshalling`. Serializes/deserializes `Marshalled<T>` objects to/from JSON using `base-json` as the wire format engine. Replaced a previous Jackson-based implementation.

**Key types:**

| Type | Role |
|---|---|
| `JsonTransport` | Extends `AbstractTransport<JsonTransport>`; `write(Marshalled<?>, Writer)`, `read(Reader)`, `read(Reader, Marshaller)`, `register(Codec<?>)` |
| `Codec<T>` | `codecClass()`, `encode(transport, parameter, value, marshaller)`, `decode(transport, parameter, value, marshaller)` |
| `ConditionalCodec<T>` | Extends `Codec<T>`; adds `ignore(T)` and `defaultValue()` — fields are omitted from JSON when `ignore` returns true |

**Wire format:** Every marshalled object serializes as a `JsonObject` with a mandatory `"@type"` field (fully-qualified class name) followed by schema parameter fields. Abstract/interface/`Object`-typed fields use a two-field envelope `{"@type":"…","value":…}`.

**Built-in codecs:**

| Java type | JSON representation |
|---|---|
| `String`, `Character` | `JsonString` |
| `Integer`, `Long`, `Byte`, `Float`, `Double` | `JsonNumber` |
| `Boolean` | `JsonBoolean` |
| `BigDecimal`, `BigInteger` | `JsonString` (precision-preserving `.toString()`) |
| `Instant`, `LocalDate/Time/DateTime`, `ZonedDateTime`, `Period` | `JsonString` (ISO-8601) |
| `Duration` | `JsonNumber` (nanoseconds as long) |
| `Date`, `Timestamp` | `JsonNumber` (epoch milliseconds) |
| `Optional<T>` | `JsonArray`: `[]` empty, `[element]` present; omitted when empty |
| `Streamable<T>` | `JsonArray` of elements; omitted when empty |

**Encoding dispatch:** null → `JsonNull` → `Marshalled` → `Transformer` → `Codec` → `@Marshal`-able → abstract-type envelope → `IllegalStateException`.

**Schema pruning on decode:** Candidate schemas are pruned field-by-field as JSON is parsed; unknown fields throw `IllegalStateException` immediately — extra JSON fields are not tolerated.

**Gotchas:**
- `"@type"` is a reserved field name — any schema parameter literally named `@type` collides with the envelope.
- `BigDecimal`/`BigInteger` are JSON strings, not numbers — not interoperable with systems expecting numeric JSON values.
- `Duration` is nanoseconds (numeric), not ISO-8601 — differs from `Instant` and date/time types.
- `Optional.empty()` and `Streamable.empty()` are omitted entirely from output; round-trip relies on `ConditionalCodec.defaultValue()`.
- Null elements inside `Streamable` are silently dropped during encoding.
- `@type` class loading uses `Class.forName(name)` — fails across custom/OSGi classloaders.
- `read(Reader, Marshaller)` is required when the type has `@Bound` parameters; the transport does not inject them itself.

**Dependencies:** `build.base.json`, `build.base.marshalling`, `build.base.transport`, `build.base.foundation`, `java.sql`.

### base-query

**Purpose:** Annotation-driven in-memory object index with fluent, supertype-aware query DSL. Objects opt in via `public static final Function` fields annotated `@Indexable`; the index maintains dual forward/reverse hash maps for O(1) lookup by extracted value, with automatic fallback to composite traversal for non-indexed scopes.

```java
index.match(Foo.class)          // finds Foo and all indexed subclasses
     .where(Foo.NAME).isEqualTo("bar")
     .scope(Scope.DepthFirst)
     .findAll();
```

**Public API:**

| Type | Role |
|---|---|
| `@Indexable` | On a `public static final Function` field: value-based index entry. On a type: syntactic marker (accepted but field-level annotation is canonical). |
| `@Unique` | Combined with `@Indexable`: enforces uniqueness per key; enables O(1) single-object lookups. |
| `@Dynamic` | Combined with `@Indexable`: declares the extracted value may change post-construction; enables `reindexDynamic`. |
| `Index` | Write surface: `index(obj)`, `unindex(obj)`, `reindex(obj)`, `reindexDynamic(obj)`, `add(Class,T)`, `remove(Class,T)` |
| `Queryable` | Read-only surface: `match(Class)`, `get(Class, Function, key)` |
| `AbstractHeapBasedIndex` | Thread-safe core impl (dual `ConcurrentHashMap` forward/reverse maps per `@Indexable` field); `traverse` hooks are abstract for subclass traversal strategies |
| `HeapBasedIndex` | Concrete `AbstractHeapBasedIndex` with empty traversal (index-only; no composite backing) |
| `Scope` | `Indexed` (hash-only), `Direct`, `DepthFirst`, `BreadthFirst` — controls fallback traversal depth |
| `Match` / `Condition` / `Terminal` | Fluent query chain: `match → where → isEqualTo/isNotEqualTo/matches → findAll/findFirst/get` |

**Key behaviors:**

- **Supertype-aware queries:** `match(Shape.class)` finds indexed `Circle` and `Square` instances by scanning all assignable classes in the index. Applies to both `@Unique` and non-unique indexes, and to `objectByClass` membership.
- **`reindex(obj)`:** Full `unindex` + `index` cycle. Uses the stored reverse map for unindex so it is safe to call even after the object's state has already changed.
- **`reindexDynamic(obj)`:** Partial update touching only `@Dynamic`-annotated fields. Reads the old value from the reverse map, removes it, re-invokes the function on the current object state, and inserts the new value. Stable fields are untouched. Compatible with `@Unique @Dynamic`.
- **`add(Class, T)`:** Registers the object in `objectByClass` only — does NOT invoke any `@Indexable` functions. Fallback linear scan applies to `where(...).isEqualTo(...)` queries for these objects.
- **`unindex`:** Always uses the stored reverse map — never re-invokes the function. Safe even when the object's indexed property has already changed.
- **Null values:** Indexed via a `NULL_OBJECT` sentinel so `null` extracted values are fully supported, including on the `isEqualTo(null)` fast path.

**Gotchas:**
- `@Indexable` on non-`public static final Function` fields is silently ignored.
- `@Unique` carves the field out of the non-unique index — omitting it disables uniqueness enforcement.
- `getOrNull()` returns `null` for both "no match" and "more than one match" — use `getOrThrow()` to distinguish.
- `Scope` propagation: scope set on `Match` is inherited by the terminal; a later `.scope()` call on the terminal overrides it.
- The `putIfAbsent` uniqueness check in `reindexDynamic` is not transactional with the remove — concurrent calls on the same object may observe partial state.

**Dependencies:** `base-foundation`.

### base-mereology

**Purpose:** Part-whole hierarchy modeling and traversal (mereology = the study of parts and wholes). Implements BFS/DFS traversal of `Composite` trees with cycle detection, reflexive inclusion, subtree exclusion, and ancestry context via `Entity<T>`. Also provides `HeapBasedCompositeIndex` which bridges composite traversal into the `base-query` framework.

**Public API:**

| Type | Role |
|---|---|
| `Composite` | `@FunctionalInterface`; `iterator(Class<T>)` returns direct parts of type T |
| `Composites` | Utility: `of(parts...)`, `keysOf(Map)`, `valuesOf(Map)`, `verify(Composite, Predicate)` |
| `Traversal<T,B>` | Fluent builder: `strategy()`, `reflexive()`, `filter(Class)`, `filter(Predicate)`, `exclude(Predicate<Composite>)`, `abort(Predicate)`, `stream()`, `hierarchical()`, `iterator()` |
| `Strategy` | `Direct`, `DepthFirst`, `BreadthFirst` |
| `Hierarchical<T>` | `Iterable<Entity<T>>` with ancestry context; `abort(Predicate<Entity<T>>)` for early exit |
| `Entity<T>` | `object()`, `composite()` (direct parent), `hierarchy()` (boundary-to-parent ordered list), `distance()`, `isBoundary()`, `isAtom()` |
| `HeapBasedCompositeIndex` | Extends `AbstractHeapBasedIndex`; overrides `traverse(Class, Scope)` and `traverse(Scope)` to delegate to a backing `Composite` with the corresponding `Strategy` |

**Key behaviors:**

- **`Composites.verify(root, suspect)`:** Diagnostic utility. Traverses all reachable composites from `root`, filters to those matching the `suspect` predicate, then returns the subset that expose no parts (`iterator(Object.class).hasNext() == false`). Useful for detecting incorrectly wired composites that should have parts but don't.
- **Cycle detection:** Identity-based (`IdentityHashMap`). A `Composite` appearing twice by reference (diamond DAG) is visited once. A self-referencing composite is yielded as an element but not recursed into.
- **`Entity.hierarchy()`:** Returns composites ordered from outermost boundary to direct parent (boundary-first). The DFS iterator internally accumulates innermost-first from the stack and reverses for storage; BFS builds the list explicitly and reverses it.
- **`Entity.distance()`:** Number of enclosing composites. Directly-enclosed objects have distance 1.
- **`filter(Class)` ordering constraint:** Must be called before `filter(Predicate)` and `abort(Predicate)`. Calling it after a predicate/abort has been set throws `IllegalStateException`.
- **`abort(Predicate)`:** Consumes the aborting element without yielding it to the caller.
- **Traversal reusability:** Each call to `stream()` or `iterator()` on a `Traversal` creates a fresh iterator — repeated calls are safe.
- **Deduplication in transitive traversal:** The framework calls both `iterator(Composite.class)` and `iterator(elementClass)` and deduplicates by identity, so an object that is both a `Composite` and the target type is yielded exactly once.

**Gotchas:**
- Default strategy is `Direct` (immediate children only) and not reflexive (root excluded from results).
- `filter(Class)` must precede any predicate/abort configuration or `IllegalStateException` is thrown.
- `abort(Predicate)` stops traversal without yielding the matching element.
- `HeapBasedCompositeIndex` falls back to composite traversal only when the indexed scope has no hits — the backing `Composite` is the fallback, not the primary source.

**Dependencies:** `base-foundation`, `base-query`.

### base-json

**Purpose:** Immutable JSON value tree library aligned with the in-progress JEP 8344154 API. Provides parsing, building, and writing for all six JSON value types, with no external dependencies beyond `base-parsing`.

**Value type hierarchy** (all `sealed`):
```
JsonValue (sealed interface)
├── JsonString   — wraps String; factory: JsonString.of(String)
├── JsonNumber   — wraps Number; factory: JsonNumber.of(Number)
├── JsonBoolean  — wraps boolean; constants TRUE/FALSE; factory: JsonBoolean.of(boolean)
├── JsonNull     — singleton INSTANCE
├── JsonObject   — ordered Map<String,JsonValue>; factory: JsonObject.of(Map) / JsonObject.builder()
└── JsonArray    — List<JsonValue>; factory: JsonArray.of(List) / JsonArray.builder()
```

Each interface is `sealed` permitting exactly one package-private `record` implementation. The sealed hierarchy supports exhaustive `switch` pattern matching.

**Entry point and key APIs:**

| Type | Role |
|---|---|
| `Json` | Static façade: `Json.parse(String/byte[]/Reader)`, `Json.write(JsonValue, Writer)`, `Json.write(JsonValue, Writer, JsonFormat)`, `Json.of(Object)`, `Json.array(...)`, `Json.object(Map)` |
| `JsonValue` default methods | `asObject()`, `asArray()`, `asString()`, `asNumber()`, `asBoolean()` — upcast or throw `JsonAssertionException`; `get(String)`, `getString(String)`, `element(int)`; `toJsonString()` / `toJsonString(JsonFormat)` |
| `JsonObject.Builder` / `JsonArray.Builder` | Fluent builders via `put(key, …)` / `add(…)`, `build()` |
| `JsonFormat` | `COMPACT` (no whitespace) or `PRETTY` (2-space indent, one member per line) |
| `JsonParseException` | Unchecked; carries `line()`, `column()`, `offset()`, `path()` (JSON-pointer-style: `/users/0/age`) |
| `JsonAssertionException` | Unchecked; thrown by `asX()` / `get()` / `element()` on type mismatch or absent key/index |

**Number precision:** parser produces `Long` (fits in long), `BigInteger` (oversized integer), or `BigDecimal` (decimal/exponent) — never `double` or `float`.

**Parsing implementation:** `JsonReader` extends `AbstractParser<JsonValue>` from `base-parsing`. Uses `Rule.define()` for the recursive `value` rule. Nesting depth is capped at 500 levels.

**Gotchas:**
- `get(name)` throws `JsonAssertionException` when the key is absent — call `has(name)` first for optional fields.
- `JsonObject` silently overwrites duplicate keys during parsing (last value wins).
- `Json.of(Object)` does not accept an existing `JsonValue` — passing one throws `IllegalArgumentException`.
- Numbers from the parser are never `int`, `float`, or `double`; only `Long`, `BigInteger`, `BigDecimal`.
- Trailing content after a valid value throws: `Json.parse("true false")` fails.
- Control characters (< U+0020) inside string literals are rejected as per the JSON spec.
- `toString()` on `JsonObjectImpl` / `JsonArrayImpl` returns compact JSON, not a Java-style representation.

**Dependencies:** `build.base.parsing` (and transitively `build.base.io`, `build.base.foundation`).

### base-parsing

**Purpose:** Generic parser infrastructure for the `base` family. Provides two complementary parsing layers: a `Rule<T>` combinator framework for composable grammar fragments, and `AbstractParser<T>` for full-grammar parsers. Also provides character-level I/O (`ScannerInput` with backtracking), a configurable `Scanner`, an operator-precedence `ExpressionParser`, and a linear `TemplateParser`.

**Layer A — full-grammar parsers:**

| Type | Role |
|---|---|
| `Parser<T>` | `@FunctionalInterface`; single `run()` method |
| `AbstractParser<T>` | Base class; owns `Scanner` lifecycle; subclasses implement `parse()` (grammar) and `translate(ParseException)` (exception mapping) |

**Layer B — combinator rules:**

| Type | Role |
|---|---|
| `Rule<T>` | `@FunctionalInterface`; `tryParse(Scanner)` returns `Optional<T>` (soft fail) or throws `ParseException` (hard fail) |
| Combinators | `map`, `filter`, `or`, `then`, `repeated`, `repeated1`, `separatedBy`, `zip`, `optional`, `between`, `times`, `atLeast`, `atMost`, `not`, `label`, `require`, static `define()` (recursive rules), `endOfInput()` |

**Character I/O:**

| Type | Role |
|---|---|
| `ScannerInput` | Interface: character-level I/O with `save()`/`restore(checkpoint)` backtracking API |
| `StringInput` | `ScannerInput` backed by `char[]`; full backtracking support |
| `LookaheadReaderInput` | `ScannerInput` backed by `LookaheadReader`; no backtracking |
| `Scanner` | Stateful scanner over `ScannerInput`; `Filter` support; `follows`, `consume`, `skip*`, `consumeUntil`, `consumeWhile`, `consumeBalanced` |
| `Filter` | `Consumer<ScannerInput>`; built-in: `WHITESPACE`, `JAVA_SINGLE_LINE_COMMENT`, `JAVA_MULTILINE_COMMENT` |
| `Evaluator<T>` | `Predicate<Scanner> & Function<Scanner, T>`; pattern-to-typed-value converter |

**Tokenizer / expression pipeline:**

| Type | Role |
|---|---|
| `Token<N>` | Record: `(TokenParser<N>, Location, String value)` |
| `Tokenizer<N>` | String → `List<Token<N>>` via registered `TokenParser`s |
| `ExpressionParser<N>` | Operator-precedence (shunting-yard) expression parser; `defineAtom/defineUnary/defineBinary/defineSection` |
| `TemplateParser<N>` | Linear template tokenizer; returns `List<N>` with optional adjacent-node merging |

**`AbstractParser` lifecycle:**
```
run() → registerFilters(scanner) → parse() → assert fully consumed → return
       catch ParseException → translate(cause) → throw domain exception
```
Helpers available in `parse()`: `expect(String)`, `expect(Pattern, desc)`, `followsKeyword(String)`, `consumeKeyword(String)`.

**`Rule.define()` for recursive grammars:**
```java
Rule<Node> value = Rule.define(self ->
    objectRule.or(arrayRule).or(stringRule).or(numberRule));
```
Uses `AtomicReference` to wire a self-placeholder before the rule is constructed. Left recursion causes `StackOverflowError`.

**Gotchas:**
- `Rule.or()` and `Rule.not()` require backtracking — they throw `UnsupportedOperationException` at parse time when the `Scanner` was built from a `Reader` (`LookaheadReaderInput`).
- `AbstractParser.scanner` is not thread-safe — do not share an `AbstractParser` instance across threads during `run()`.
- `zip(other, fn)` does not restore on partial failure: if left succeeds but right returns empty, consumed input is gone.
- `ExpressionParser` throws `ExpressionParserException`, not `ParseException` — code catching `ParseException` from a `Rule.tryParse()` call misses these.
- `Scanner` patterns without `^` are auto-anchored to current position; patterns starting with `^` are treated as line-start assertions (column 1 only).
- `StringInput.save()` appends snapshots without bound — a grammar with many `or` branches accumulates them for the `Scanner`'s lifetime.
- `ExpressionParser.parse` returns `null` for blank input; `TemplateParser.parse` returns `List.of()`.
- `available()` has side effects (applies filters).

**Dependencies:** `build.base.foundation`, `build.base.io` (re-exported as `transitive`).

### base-graph

**Purpose:** Immutable directed/undirected graph library with a comprehensive set of algorithms: BFS/DFS traversal, topological ordering, cycle detection, shortest paths (unweighted and weighted), strongly connected components, and transitive reduction. Zero production dependencies — self-contained.

```java
Graph<String> g = Graph.<String>directed()
    .addEdge("A", "B")
    .addEdge("B", "C")
    .build();

List<String> order = Graphs.topologicalSort(g); // [C, B, A] — dependencies first
Optional<Path<String>> path = Graphs.shortestPath(g, "A", "C");
```

**Graph types:**

| Type | Description |
|---|---|
| `Graph<V>` | Immutable simple directed or undirected graph |
| `WeightedGraph<V,W>` | Immutable graph with typed edge weights; Dijkstra-capable |
| `Multigraph<V>` | Immutable graph permitting multiple parallel edges |

**Edge types:**

| Type | Description |
|---|---|
| `Edge<V>` | Record with value equality on `(from, to)` |
| `WeightedEdge<V,W>` | Record with weight; `toEdge()` strips weight |
| `MultiEdge<V>` | Reference identity (intentionally no equals/hashCode) for parallel edges |

**Algorithm classes:**

| Class | Algorithms |
|---|---|
| `GraphTraversal` | `breadthFirstSearch`, `depthFirstSearch`, `reachableFrom`, `ancestors`, `descendants` |
| `GraphOrdering` | `topologicalSort` (Kahn's), `parallelizableGroups` (layered Kahn) |
| `GraphCycles` | `hasCycle`, `findCycle` (returns `Optional<List<V>>` where list begins and ends with same vertex) |
| `GraphPaths` | `shortestPath` (BFS), `shortestPath` (Dijkstra with caller-supplied `zero` + `add`) |
| `GraphConnectivity` | `stronglyConnectedComponents` (iterative Tarjan, directed only) |
| `GraphReduction` | `transitiveReduction` (directed only; O(V·(V+E))) |
| `Graphs` | Convenience facade delegating to all domain classes |

**Key design decisions:**

- Fully immutable after `build()`; insertion-ordered vertices (`LinkedHashSet`).
- Pluggable collection backend via `GraphCollections` strategy — enables fastutil substitution.
- DFS/SCC use iterative explicit stacks (no `StackOverflowError` on deep graphs).
- **Edge direction semantics in ordering:** `A → B` means A depends on B. Nodes with no outgoing edges (no dependencies) are processed first in `topologicalSort`. This is the build/scheduler convention.
- `parallelizableGroups` returns `List<Set<V>>` — index 0 is independent leaf nodes; each set in the same layer can be processed concurrently.
- `Multigraph.Builder.addEdge()` is **non-fluent** — it returns the new `MultiEdge`, not the builder.

**Gotchas:**
- `reachableFrom` excludes `start` itself unless there is a cycle back to it.
- `stronglyConnectedComponents` requires a directed graph; returns components in reverse topological order of the condensation DAG (sinks first).
- Dijkstra requires caller-supplied `W zero` and `BinaryOperator<W> add`; no support for negative weights.
- `WeightedGraph`: if multiple edges are added between the same pair, the last weight wins silently.

**Dependencies:** None (production). JUnit 5 + AssertJ (test only).

### base-template

**Purpose:** JPMS-native compile-time template library. Templates are authored as `.jt` files and compiled to Java records by `base-template-processor` at build time. `HtmlOut` HTML-escapes all `write()` calls; `TextOut` passes values through verbatim.

| Type | Role |
|---|---|
| `Template<O extends Out>` | `@FunctionalInterface`; one method: `render(O out)` |
| `Out` | Abstract output sink; `raw(String)` writes unescaped; buffers to `StringBuilder` or streams to `Writer`; `content()` returns the buffer and throws `IllegalStateException` when Writer-backed (`toString()` returns `""` in that case) |
| `HtmlOut` | Extends `Out`; `write(Object)` HTML-escapes `& < > " '` — safe for user-supplied values in HTML |
| `TextOut` | Extends `Out`; `write(Object)` writes `String.valueOf(value)` unescaped — for plain-text output |
| `JavaOut` | Extends `Out`; verbatim `write(Object)`; `@OutSyntax(prefix = "%", interpolation = "${")` so Java annotations and `#{` in generated source need no escaping |
| `@OutSyntax` | Annotation on an `Out` type declaring its default directive prefix and interpolation opener; read by the processor via `javax.lang.model`, `CLASS` retention, `@Inherited` |
| `@ProcessTemplates` | Module-level annotation; marks a module as containing `.jt` files; `RetentionPolicy.SOURCE` |

**Template syntax (`.jt` files):**
```
out HtmlOut;

package com.example;
import java.util.List;

template TasksTemplate(String title, List<String> items) {
<h1>#{title}</h1>
<ul>
@for (var item : items) {
  <li>#{item}</li>
@}
</ul>
@end
```
- The header is read in a fixed order: `out <Type>;` (required, must be first; the `Out` class, simple or qualified, the template writes to), then optional `option` lines, then optional `package` and `import` lines (which belong to the generated Java record; an omitted `package` is inferred from the file's directory under `src/main/jt`, and a declared one is checked against it), then `template Name(params) {`
- A file holds exactly one template. The declaration must end with `{`, and the body must end with an `@end` line; anything after `@end` is an error
- `#{expr}` — interpolated expression; calls `out.write(expr)`
- A line starting with `@` is a directive only when the word after it is in the closed set: `for if else while switch case default do try catch finally var final` (the line, minus `@`, is emitted as Java), `@}` (closing brace, may continue as `@} else {`), `@include`, `@fragment`, `@endfragment`, `@java` and `@end`. Any other `@` line is plain text, so `@Override`, `@media` and `@click=...` need no escape. `slot` and `flush` are reserved and rejected until implemented
- `@fragment name(Type param, ...)` … `@endfragment` — a part of the template that is rendered in place, by `new Name(param, ...).render(out)` with the variables of the same names, and is also generated as a nested record `Name` (the name with its first letter upper-cased) implementing `Template<Out>`, so it can be rendered on its own (`new TasksPage.Row(task)`). A fragment sees only its parameters, not the template's: it is a separate type. Fragments do not nest, must be closed, must contain whole blocks, and need distinct names that differ from the template's. The generated type must not share its name with a type the template imports, gets from `java.lang`, or names in a parameter list (checked); nor with a type of the template's own package (not checked, and javac reports it)
- `@java <statement>` — any other Java statement, emitted into `render()` (for example `@java out.raw(x);`)
- `@include <expr>` — calls `<expr>.render(out)` for sub-template composition; the expression is required
- `@include Layout(args) {` … `@}` — an include with a body: the lines up to the matching `@}` become a `Template<Out>` (an anonymous class, so `out` keeps its name) that is passed to the included template as its last argument, as `new Layout(args, <body>).render(out)`. The body sees what is around it, which must be effectively final. The `@}` must be on a line of its own, and bodies nest. The layout declares a `Template<Out>` parameter for the body, last, and renders it with `@include body`
- `out` is an implicit variable inside `render`, so `@java` can call it directly (`@java out.raw(...);`)
- Escapes: `@@` at the start of a line emits a literal `@` (for a text line that would otherwise be a directive); `##{` emits a literal `#{`
- Delimiters are configurable per template with `option` lines immediately after the `out` declaration. They override the defaults the `Out` type declares with `@OutSyntax` (inherited by subclasses; `JavaOut` declares `%` and `${`; any `Out` without the annotation uses `@` and `#{`): `option prefix = "%";` replaces `@`, and `option interpolation = "${";` replaces `#{` (it must end with `{`). The escapes follow: the prefix doubled, and the interpolation's first character doubled (`$${`). Values are plain double-quoted strings and the prefix must not start with an identifier character
- `package` / `import` / `import static` / `import static ... .*` all supported in header

**Usage:**
```java
var out = new HtmlOut();
new TasksTemplate("My Tasks", List.of("Buy milk", "Walk dog")).render(out);
String html = out.toString();
```

**Dependencies:** None (runtime). `base-parsing` (processor compile-time only).

### base-version

**Purpose:** Immutable version parsing, comparison, and range/constraint evaluation. Supports a relaxed SemVer-inspired format with `sequence[-prerelease][+build]` structure. Zero dependencies beyond the JDK.

```java
Version v = Version.parse("1.2.3-SNAPSHOT");
VersionConstraint c = VersionConstraint.parse("[1.0,2.0)");
boolean match = c.test(v);  // true

List<Version> sorted = versions.stream()
    .sorted(VersionOrder.MAVEN)
    .toList();
```

**Key types:**

| Type | Role |
|---|---|
| `Version` | Immutable version; `parse(String)`, `tryParse(String)` → `Optional<Version>`; implements `Comparable<Version>` |
| `Version.Element` | One token in a version segment — either `Integer` or `String`; alpha↔digit transitions split implicitly |
| `VersionOrder` | Enum `Comparator<Version>`: `NATURAL` (includes build metadata), `SEMVER` (ignores build metadata), `MAVEN` (qualifier ranking: alpha < beta < milestone < rc < snapshot < release) |
| `VersionBound` | One end of a range interval — lower (`>=`/`>`) or upper (`<=`/`<`); implements `Predicate<Version>` |
| `VersionRange` | Single contiguous interval; `parse(String)` supports Maven range syntax; implements `Predicate<Version>` |
| `VersionConstraint` | One or more `VersionRange`s OR-combined for disjoint unions; implements `Predicate<Version>` |

**Supported range syntax:**

| Syntax | Meaning |
|---|---|
| `1.0` | Exactly `1.0` |
| `[1.2,1.3]` | `1.2 ≤ v ≤ 1.3` |
| `[1.0,2.0)` | `1.0 ≤ v < 2.0` |
| `[1.5,)` | `v ≥ 1.5` |
| `(,1.0]` | `v ≤ 1.0` |
| `(,1.0),(1.0,)` | `v ≠ 1.0` (disjoint — use `VersionConstraint.parse`) |

**Gotchas:**
- `Version.compareTo` includes build metadata (unlike SemVer §10) — use `VersionOrder.SEMVER` for spec-compliant behavior.
- Sequence must start with a digit — `Version.parse("SNAPSHOT")` throws.
- `1.0` equals `1.0.0` (trailing-zero normalization); `1.0.Final` does not equal `1.0`.
- `VersionConstraint` supports at most two disjoint ranges; three or more throw.
- Integer overflow for very large numeric segments silently falls back to `String` (incorrect ordering).
- Maven `sp` (service pack) qualifier is not yet supported.

**Dependencies:** None.

### base-naming

String name = gen.next(); // e.g., "Vibrant Salva Maiorano"

~240 adjectives × ~400 first names × ~900 last names ≈ 86M unique names.
**Dependencies:** `base-foundation` (for `Primes`).

### base-network

**Purpose:** TCP client-server with serializable callable dispatch and pub-sub over connections.

| Type | Role |
|---|---|
| `Server` | Daemon-thread acceptor; maps remote identity to `Connection` |
| `Client` | Wraps `Connection`; `submit(SerializableCallable<T>)` → future result |

### base-assertion

**Purpose:** Test-time assertion helpers for `CompletableFuture<T>`, `Retryable<T>`, and `Iterator`/`Streamable` pattern matching.

```java
Eventually.assertThat(myFuture).withTimeout(timeout).isCompleted();
Eventually.assertThat(myRetryable).isEqualTo(expectedValue);
Eventually.assertThat(myStreamable).starts().then().matches(e -> e.isValid()).isTrue();
```

| Type | Role |
|---|---|
| `Eventually` | Entry point: `assertThat(CompletableFuture)`, `assertThat(Retryable)`, `assertThat(Iterable/Streamable)` |
| `CompletableFutureAssertion<T>` | Waits then asserts: `isCompleted()`, `isCompletedWithValue(T)`, `isCompletedExceptionally()`, `isCancelled()` |
| `RetryableAssertion<T>` | Polls via `BlockingRetry`: `isEqualTo(T)`, `isCompleted()`, `isCompletedExceptionally()` |
| `IteratorPatternMatcherRetryableAssertion<T>` | Retrying iterator pattern DSL: `.starts()`, `.then()`, `.matches(...)`, `.times(n)`, `.ends()` |

**JPMS note:** The test module declares `opens build.base.assertion.test to org.junit.platform.commons` — this is required for JUnit's reflection-based test discovery on the module path.

### base-telemetry

**Purpose:** Pure API — telemetry type hierarchy and `TelemetryRecorder` contract. No implementations here. Designed for end-user-facing diagnostics (IDE/tool integration).

| Type | Role |
|---|---|
| `TelemetryRecorder` | Abstract recording API; `info`, `warn`, `error`, `fatal`, `diagnostic`, `commence` |
| `Activity` / `Meter` | `AutoCloseable` in-progress operations; `Meter` adds `progress()` |
| `Telemetry` subtypes | `Information`, `Advice`, `Notification`, `Warning`, `Error`, `Fatal`, `Diagnostic`, `Commenced`, `Completed<T>`, `Progress` |
| `Location` / `TextualPosition` / `TextualRange` | Source location attached to telemetry |
| `NamedUnit` | Singular/plural display unit for `Meter` progress; `NamedUnit.none()` for unitless |

**Gotchas:**
- `locations()` returns a `Stream` — one-shot; implementations must cache and re-stream.
- `Fatal` is both `ExceptionalTelemetry` and `ImplementationTelemetry` — developer-facing, not end-user.
- `Progress` never has locations.
- `NamedUnit.of("", "")` throws — use `NamedUnit.none()` for empty units.

**Dependencies:** None.

### base-telemetry-foundation

**Purpose:** Concrete `TelemetryRecorder` implementations.

| Impl | Behavior |
|---|---|
| `AbstractTelemetryRecorder` | Template; single abstract `record(T)` hook; implements `Activity`/`Meter` lifecycle |
| `NoOpTelemetryRecorder` | Silent discard |
| `PrintStreamTelemetryRecorder` | Configurable output/error stream routing |
| `SystemTelemetryRecorder` | `System.out` / `System.err` (captured at construction time) |
| `MessagerBasedTelemetryRecorder` | Annotation-processor `javax.tools.Messager` adapter; first location wins |
| `ObservableTelemetryRecorder` | Decorator that captures all telemetry for test assertions |

**Gotchas:**
- `ObservableTelemetryRecorder` does not observe `Activity`/`Meter` telemetry directly — `Commenced`, `Progress`, and `Completed` events go through the underlying recorder, not the observable's `record()`.
- `Meter.progress()` has a documented minor race condition between the done-check and the record call.
- `MessagerBasedTelemetryRecorder` silently drops all but the first `Element`/`AnnotationMirror`/`AnnotationValue` location.

**Dependencies:** `base-foundation`, `base-telemetry`, `java.compiler`.

### base-telemetry-ansi

**Purpose:** ANSI terminal `TelemetryRecorder` with live in-terminal progress bars. Virtual Thread render loop fires every 1 second.

- Non-progress telemetry prints inline with ANSI clear-line escape (`\u001b[0K`).
- `ProgressBar` renders: ANSI green percentage, ANSI blue `#`-filled 20-char bar, count label with unit, and elapsed/remaining time estimates after 3 seconds.
- Completed `ProgressBar` slots are nulled out and reused to keep the display stable.

**Gotchas:**
- Not safe for non-ANSI terminals — no capability detection; escape codes appear as literal garbage.
- Forgetting to call `close()` leaks the virtual render thread.
- `ProgressBar.close()` does not call `ProgressBar.complete()` — it delegates to the underlying `Meter`.
- `System.out` is hardcoded — no configurable output stream.

**Dependencies:** `base-foundation`, `base-telemetry-foundation` (transitive), `java.compiler`.

## Data Flow

### Marshalling → JSON Transport

```mermaid
sequenceDiagram
    participant C as Caller
    participant M as Marshaller
    participant J as JsonTransport
    participant JV as base-json (JsonValue)

    C->>M: marshal(myObject)
    M->>M: invoke @Marshal method with Out<T> params
    M-->>C: Marshalled<T> (schema + values)

    C->>J: write(marshalled, writer)
    loop each parameter
        J->>J: resolve Codec / Transformer / Schema
        J->>JV: build JsonObject / JsonArray / JsonString / JsonNumber
    end
    J->>JV: toJsonString() → compact JSON string
    J-->>C: written to Writer
```

### Configuration Population from CLI

```mermaid
sequenceDiagram
    participant App as Application
    participant P as CommandLineParser
    participant CB as ConfigurationBuilder
    participant CFG as Configuration

    App->>P: parse(args[])
    P->>P: prepend env-var-derived args
    P->>P: split on "=" globally
    loop each arg
        P->>P: longest-prefix match
        P->>CB: add(Option instance via static factory)
    end
    P-->>App: ConfigurationBuilder
    App->>CFG: ConfigurationBuilder.build()
```

### Retryable Execution

```mermaid
sequenceDiagram
    participant C as Caller
    participant BR as BlockingRetry
    participant R as Retryable<T>
    participant RF as RetryFrequency

    C->>BR: get()
    loop until timeout or done
        BR->>R: get()
        alt EphemeralFailureException
            BR->>RF: next() → Duration
            BR->>BR: sleep(duration)
        else PermanentFailureException
            BR-->>C: throw PermanentFailureException
        else success
            BR-->>C: return T
        end
    end
```

### Graph Algorithm Flow

```mermaid
sequenceDiagram
    participant C as Caller
    participant B as Graph.Builder
    participant G as Graph<V>
    participant A as GraphOrdering

    C->>B: directed().addEdge(A,B).addEdge(B,C).build()
    B-->>C: Graph<V> (immutable)
    C->>A: topologicalSort(graph)
    A->>A: Kahn's algorithm — process zero-out-degree nodes first
    A-->>C: List<V> in dependency order
```

## Conventions

### Naming
- All public packages: `build.base.<module-name>` (e.g., `build.base.foundation`, `build.base.transport.json`)
- Static factory methods: `of(...)`, `create(...)`, `empty()`, `get()`
- Abstract base classes: `Abstract*` prefix
- Functional interfaces: used extensively; prefer lambdas over anonymous classes

### Design Patterns in Use
- **Heterogeneous container** — `Configuration` keyed by `Class<? extends Option>`
- **Output parameter** — `Out<T>` in `@Marshal` methods
- **Returns-its-argument validation** — `Preconditions` returns the validated value
- **Lazy by default** — `Lazy<T>`, `LazilyMapped`, `TransformingIterable`, `Streamable.map/filter`
- **Null-avoidance** — `Optional`, `Lazy<T>`, `Capture<T>`, `Exceptional<T>` — raw `null` propagation is rare
- **Pluggable strategies** — `Hasher<K>`, `Predicate<T>`, `RetryFrequency`, `Transformer`, `Codec`, `GraphCollections`
- **Immutable value objects** — `Graph`, `WeightedGraph`, `Version`, `VersionRange`, `Path`, `WeightedPath`

### Configuration Pattern
Every module that is configurable follows this pattern:
```java
Configuration config = new ConfigurationBuilder()
    .add(Timeout.ofSeconds(30))
    .add(HostName.of("example.com"))
    .build();

Timeout timeout = config.get(Timeout.class); // uses @Default if not explicitly set
```

### Module System (JPMS)
All modules use JPMS `module-info.java`. Most are open modules (allowing deep reflection for the marshalling infrastructure). Test dependencies are on the classpath (not the module path). Test modules that run on the module path (like `base-assertion`) must declare `opens <test.package> to org.junit.platform.commons`.

## Gotchas

1. **`-parameters` compiler flag is required** for `base-marshalling` to correctly resolve parameter names. Without it, parameters default to `arg0`, `arg1`, etc.

1a. **`@Unmarshal` on a method (not a constructor) is a hard registration error** — `ConcurrentSchemaFactory.register` throws `IllegalArgumentException` if any `@Unmarshal`-annotated methods (not constructors) are found. The map previously said this was silently ignored — it is not.

1b. **`Marshalling.registerEnum` stores enums in a separate registry** (`enumSchemasByClass`). Code that iterates `marshallingSchemasByClass` directly will not see registered enums. `isMarshallable` and `getMarshallingSchema` check both registries.

1c. **`MethodHandles.Lookup` must be the class's own lookup** — `Marshalling.register(MyClass.class, lookup)` requires `lookup.lookupClass() == MyClass.class`. Passing a foreign lookup throws `IllegalArgumentException`.

2. **`Subscriber` is single-use** in `base-flow`. Reuse across publishers throws `IllegalStateException`.

3. **`request(n)` in `base-flow` is a setter, not an increment** — multiple `request()` calls do not accumulate; the last call wins.

4. **`@Indexable` on non-`public static final` fields** is silently ignored in `base-query`.

4a. **`@Unique` carves the field out of the non-unique index** in `base-query` — omitting `@Unique` on a function you intend to be unique disables uniqueness enforcement silently.

4b. **`add(Class, T)` does NOT invoke `@Indexable` functions** in `base-query` — it only registers membership in `objectByClass`. `where(fn).isEqualTo(x)` queries for these objects fall through to the linear scan fallback.

4c. **`getOrNull()` returns `null` for both "no match" and "more than one match"** in `base-query` — use `getOrThrow()` if you need to distinguish these cases.

4d. **`Traversal.filter(Class)` must be called before `filter(Predicate)` and `abort(Predicate)`** in `base-mereology` — calling it after a predicate has been set throws `IllegalStateException`.

4e. **`Traversal.abort(Predicate)` consumes the aborting element without yielding it** in `base-mereology` — the element that matches the abort predicate is not returned to the caller.

5. **`get(MappedOption.class)` always returns null** in `Configuration` — use `get(class, key)` for mapped options.

6. **Java serialization** in `base-network` — both client and server must share identical class definitions.

7. **`RetryFrequency.within(floor, ceiling)` has inverted guards** — valid inputs throw `IllegalArgumentException` (latent bug).

8. **`"@type"` is a reserved field name** in `base-transport-json` — any schema parameter literally named `@type` collides with the wire envelope.

8a. **`BigDecimal`/`BigInteger` serialize as JSON strings**, not JSON numbers — not interoperable with tools expecting numeric JSON values.

8b. **`Duration` encodes as nanoseconds (numeric)**, not ISO-8601 — differs from `Instant` and all date/time types which use ISO-8601 strings.

8c. **Null elements in a `Streamable` are silently dropped** during `JsonTransport` encoding — the decoded `Streamable` will have fewer elements.

8d. **`base-json` `get(name)` throws, not returns null** — `JsonObject.get(name)` throws `JsonAssertionException` when the key is absent. Call `has(name)` first for optional fields.

8e. **`base-json` nesting depth is capped at 500** — inputs exceeding this throw `JsonParseException` rather than causing a stack overflow.

10. **`=` is globally split before parsing** in `base-commandline` — `--option=foo=bar` becomes three tokens.

11. **`LazilyMapped.isPresent()` delegates to the underlying** — a mapped value is considered "present" even if the mapping function would return `null`.

12. **`Progress.percentage()` uses integer division** in `base-telemetry`.

13. **`base-expression` EL package is not exported** — `el.ValueExpressionImpl` and friends are module-internal; access them through the Jakarta EL API (`ExpressionFactory`, `ValueExpression`, etc.).

14. **`base-expression` `compat` package is deprecated** — `Processor`, `Variable`, `ProcessorBuilder` are retained for migration. Prefer the Jakarta EL API directly.

15. **`base-graph` topological sort direction** — `A → B` means A depends on B; nodes with no outgoing edges (leaf dependencies) come first. This is the build/scheduler convention, opposite to the "definition before use" convention of some other libraries.

16. **`Multigraph.Builder.addEdge()` is non-fluent** — it returns the new `MultiEdge<V>`, breaking the builder chain. Use `addVertex()` for fluent chains, then add edges separately.

17. **`base-version` sequence must start with a digit** — `Version.parse("SNAPSHOT")` and `Version.parse("RC1")` both throw `IllegalArgumentException`.

18. **`base-version` `VersionConstraint` supports at most two disjoint ranges** — three or more disjoint segments throw.

19. **`ANSIBasedTelemetryRecorder.close()` must be called** — failing to call it leaks the virtual render thread. Not calling `close()` is the only way the thread terminates.

20. **`base-archiving` `add(name, path)` silently succeeds on missing paths** — no exception or warning if the source path does not exist.

## Navigation Guide

**To add a new configuration option:**
- Create a class extending `AbstractValueOption<T>` in the appropriate module
- Add `@Default` static method for auto-detection if applicable
- Register `@CommandLine.Prefix` on static factory if it should be CLI-settable
- Files to touch: one new class file; optionally `module-info.java` exports

**To add a new marshallable type:**
- Annotate destructor method with `@Marshal`, constructor(s) with `@Unmarshal` (constructors only — `@Unmarshal` on methods throws)
- Call `Marshalling.register(MyClass.class, MethodHandles.lookup())` in a static initializer (lookup must be obtained inside the class)
- For enums: call `Marshalling.registerEnum(MyEnum.class)` in a static initializer — no lookup required
- Files to touch: the class file only

**To work with JSON values (`base-json`):**
```java
// Parse
JsonValue v = Json.parse("{\"name\": \"Alice\", \"age\": 42}");
String name = v.getString("name");           // "Alice"
long age = v.get("age").asNumber().longValue(); // 42

// Build
JsonObject obj = JsonObject.builder()
    .put("name", "Alice")
    .put("active", true)
    .build();
String json = obj.toJsonString(JsonFormat.PRETTY);

// Pattern match over the sealed hierarchy
switch (value) {
    case JsonString s -> ...
    case JsonNumber n -> ...
    case JsonBoolean b -> ...
    case JsonNull ignored -> ...
    case JsonObject o -> ...
    case JsonArray a -> ...
}
```

**To add a new JSON transport codec:**
- Implement `Codec<T>` (or `ConditionalCodec<T>` for fields that should be omitted when empty/null)
- Register via `jsonTransport.register(new MyCodec())`
- Files to touch: new `Codec` class; registration site

**To add a new retryable operation:**
- Implement `Retryable<T>` (or use `Retryable.of(supplier)`)
- Wrap in `BlockingRetry` for automatic polling
- Throw `EphemeralFailureException` for transient errors, `PermanentFailureException` for terminal ones

**To add a new telemetry recorder:**
- Extend `AbstractTelemetryRecorder` from `base-telemetry-foundation`
- Override `record(T telemetry)` and `uri()`
- Implement `factory()` if needed for programmatic creation

**To traverse a composite hierarchy:**
```java
composite.traverse(MyType.class)
    .strategy(Strategy.DepthFirst)
    .filter(t -> t.isActive())
    .stream()
    .forEach(System.out::println);
```

**To query an indexed object graph:**
```java
// Basic index query (also finds subclasses of MyType)
index.match(MyType.class)
    .where(MyType.NAME).isEqualTo("target")
    .scope(Scope.DepthFirst)
    .findFirst();

// Re-index an object after any property changes
index.reindex(obj);

// Re-index only @Dynamic fields (cheaper when stable fields didn't change)
index.reindexDynamic(obj);

// Diagnose composites that should have parts but don't
List<Composite> empty = Composites.verify(root, c -> c instanceof MyCompositeType);
```

**To build and run a CLI application:**
```java
List<String> tasks = new ArrayList<>();
CommandLineParser parser = Command.create("myapp")
    .argument("<task>...")
    .helpHandler(help -> { System.out.println(help); System.exit(0); })
    .section("Global Options")
    .option(Timeout.class)                         // uses @CommandLine.Prefix annotations
    .option(List.of("-w", "--working-dir"), WorkingDir.class, "of", "Working directory", String.class)
    .envVar("MY_TIMEOUT", "--timeout")
    .section("Output Options")
    .option(HostName.class)
    .positionalArgument(tasks::add)                // non-option tokens (e.g., task names)
    .command("compile", "Compiles Java sources")   // declarative — for help display only
    .command("test", "Runs tests")
    .category("build", "compile + test")           // declarative — for help display only
    .commandsSectionName("Tasks:")
    .build();
Configuration config = parser.parse(args).build();
Timeout timeout = config.get(Timeout.class);
// tasks list now populated with positional arguments
```

**To build a graph and run algorithms:**
```java
Graph<String> g = Graph.<String>directed()
    .addEdge("compile", "sources")
    .addEdge("test", "compile")
    .build();

List<String> order = Graphs.topologicalSort(g);     // [sources, compile, test]
List<Set<String>> layers = Graphs.parallelizableGroups(g); // concurrent execution layers
Optional<List<String>> cycle = Graphs.findCycle(g); // empty if DAG
```

**To write a compile-time template:**
- Create a `.jt` file under `src/main/jt/<package>/MyTemplate.jt`
- Annotate `module-info.java` with `@build.base.template.ProcessTemplates`
- Add `base-template` as a runtime dependency and `base-template-processor` to `annotationProcessorPaths`
- Use `#{expr}` for interpolation, `@for`/`@if`/`@}` for control flow, `@include expr` for composition, `@fragment name(params)` … `@endfragment` for a part that also renders on its own, `@include Layout(args) {` … `@}` with `@include body` in the layout for a page shell
- Choose `HtmlOut` for HTML output (auto-escapes user values) or `TextOut` for plain text

**To parse and compare versions:**
```java
Version v = Version.parse("2.1.0-SNAPSHOT");
VersionConstraint constraint = VersionConstraint.parse("[1.0,3.0)");
boolean inRange = constraint.test(v); // true

List<Version> sorted = list.stream()
    .sorted(VersionOrder.MAVEN)
    .toList();
```
